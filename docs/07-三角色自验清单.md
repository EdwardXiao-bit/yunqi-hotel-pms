登录后应落在 `/`（客户首页），侧边栏只有「客户服务」这一组。

| # | 操作 | 看哪里 | 期望 |

| 1.2 | 首页「我的预订」卡片 | 状态计数与最近 5 条 | 预订总 9 条（`R2026…` 号）；有 2 条「入住中」、2 条「已退房」、1 条「未到店」、3 条「待确认」、「1 条已取消」 |

## 2 角色二：前台（`front01`，可换 `front02` 复核）

登录后应落在 `/reception/`。**前台点管理端应被拦**。

| # | 操作 | 看哪里 | 期望 |
| --- | --- | --- | --- |
| 2.1 | 登录 `front01` | 跳转 | 落在 `/reception/`；侧边栏有前台组 + 客户组；顶部显示「前台」 |

| 2.3 | 工作台 | 四个指标盒 | 今日到店 / 在住 / 待确认 / 房态 4 态计数；下方「今日到店」「在住」「待清洁」「未来封禁区间」四块 |
| 2.4 | 左侧「预订管理」→ 点「今日到店」快捷筛选 | 列表 | 只剩今天入住的 `confirmed` 单；每行有「确认 / 取消 / 未到店」按钮（按状态显示） |

| 2.6 | 同单再点一次「确认」（或刷新后再点） | 提示 | 「只有“待确认”的预订可以确认，当前状态为“已确认”。」（状态机拦截） |
| 2.7 | 左侧「入住办理」→ 搜「张伟」或手机号 | 搜索结果表 | 命中该单；点它进入入住表单，入住人/手机/证件已带出，押金默认 `200.00` |

| 2.12 | 找一间「清洁中」→ 点「清洁完成」 | 卡片 | 变「正常」；提示成功（触发器写日志） |
| 2.13 | 找一间「正常」→ 登记维修（如 `2026-12-01` ~ `2026-12-20`） | 卡片 | 变「维修中」，卡片显示封禁区间 |

| 2.16 | 不填任何收款直接提交 | 提示 | 「还需补收 X 元」（E07，差额必须清零才能退房） |
| 2.17 | 加 2 份「自助早餐」（68.00/份）+ 补一笔收款 = 差额，提交 | 提示 | 「结算完成」；订单转「已退房」；房间转「清洁中」；再进该单提示「该订单已结算（…），不能重复结算。」（E06） |

## 4 判定与反馈

- **通过**：每步都符合“期望”，或至少出现中文提示而不是 500/白屏。
- **不通过**：截图 + 你看到的提示文字 + 地址栏 URL，我按 URL 定位到视图/模板。
