## 2 项目描述

### 2.1 一句话描述（提交材料抬头用，≤ 100 字）

> 面向中小型酒店的客房管理系统：客户按日期区间查询可用房间并在线预订，前台办理入住、退房与费用结算并调度房态，管理员维护房型、房间与价格并查看入住率和营业收入统计；数据库层用日期区间排他约束保证同一房间在重叠日期内绝不会被重复预订。

### 2.2 完整项目描述

本系统面向中小型酒店，支持客户按日期查询房间并预订，前台办理入住、续住、退房与费用结算，管理员维护基础信息并查看经营统计。系统聚焦预订—入住—退房—统计主流程，不包含会员营销、渠道直连与硬件对接。

- **客户侧**：按入住日期、离店日期、房型及人数查询可预订房间；提交、查看和取消自己的预订；查询本人历史入住及消费记录。
- **前台侧**：确认预订、处理取消和未到店，办理预订入住与散客入住、续住、提前退房及结算，维护清洁与维修状态。
- **管理员侧**：维护房型、房间、价格及员工账号，查看入住率、营业收入、热门房型和长期空闲房间等统计。

核心业务规则如下：

1. 日期区间采用 `[入住日期, 离店日期)`，离店日期必须晚于入住日期。例如，11 月 1 日入住、11 月 3 日离店，占用两个房晚，不与 11 月 3 日入住的订单冲突。
2. 房间运行状态分为正常、清洁中、维修中、停用；预订状态单独管理。指定日期是否可订，依据有效订单的占用区间及维修、停用安排判断；实际办理入住时还须确认房间已清洁且可交付。
3. 待确认、已确认及入住中的订单占用对应日期；已取消、未到店的订单释放占用。待确认订单由前台确认或取消；未到店由前台按约定到店时限核实后处理。散客入住也须建立订单并检查整个入住区间，续住须检查新增区间。
4. 预订确认时保存逐日成交价格，散客入住时保存入住区间价格，后续调价不影响已确认价格。续住新增日期按续住确认时的价格计费。提前退房按实际占用房晚结算，至少计一房晚；超时退房由前台提示并处理，本期不自动加收超时费用。
5. 退房结算金额为房费加服务费，再扣除押金，多退少补；押金不计入营业收入。数据库通过主外键、检查约束、日期区间排他约束与事务控制，统一校验预订和散客入住的房间占用，防止重叠日期重复占用。

> 口径说明：房态只表达“当下”的物理可用性（正常 / 清洁中 / 维修中 / 停用），“已预订”“入住中”由订单与入住记录推导，不写进房态字段；维修、停用的**日期区间**存 `room_block` 表，可售房夜按它扣减。

## 5 业务规则（功能清单背后的约束，报告 3.2 会用）

1. 日期区间采用 `[入住日期, 离店日期)`，离店日期必须晚于入住日期；实际计费房晚至少 1 晚。
2. 同一房间在重叠日期内不得有两个有效预订（待确认 / 已确认 / 入住中），由生成列 `during` + `EXCLUDE USING gist` 强制；散客入住同样必须先建订单，走同一条约束。
3. 维修、停用按**日期区间**登记在 `room_block`，同一房间的维修/停用区间不得重叠；新增区间与有效订单冲突时拒绝（触发器 `fn_check_room_block_order`，SQLSTATE 23514）；预订/散客入住与维修停用区间冲突时拒绝（`fn_check_reservation_block`，23514）。
4. 房态字段只表达当下物理可用性（正常 / 清洁中 / 维修中 / 停用）；“已预订”“入住中”由订单与入住记录推导，不写进房态。
5. 预订确认与散客入住时保存**逐日成交价格**到 `reservation_price`（触发器按 `rate_plan` 命中价或房型标准价逐日生成），`reservation.total_amount` 由明细汇总；后续调价不影响已确认价格，续住新增日期按续住确认时的价格计费。
6. 结算金额 = 逐日房费合计（按实际计费房晚，至少一房晚） + 增值服务费用 − 已付押金，多退少补；押金不计入营业收入，营业收入按**退房结算日期**归月。
7. 未到店（no-show）与取消必须释放房间占用；已入住的预订不可取消，已退房的预订不可再次入住；状态流转不合法时拒绝。
8. 房号在全部房间内唯一；同一房型在同一日期区间的价格方案不得重叠；被订单引用的数据不能删除（外键 `RESTRICT`），只能改为停用。

```sql
-- 同一房间在重叠日期内不得重复预订（半开区间，退房当天可再次入住）
ALTER TABLE reservation
    ADD COLUMN during daterange
    GENERATED ALWAYS AS (daterange(check_in_date, check_out_date, '[)')) STORED;

ALTER TABLE reservation ADD CONSTRAINT ex_reservation_room_overlap
    EXCLUDE USING gist (room_id WITH =, during WITH &&)
    WHERE (status IN ('pending', 'confirmed', 'checked_in'));

-- 维修/停用区间同样不允许自我重叠
ALTER TABLE room_block
    ADD COLUMN during daterange
    GENERATED ALWAYS AS (daterange(start_date, end_date, '[)')) STORED;

ALTER TABLE room_block ADD CONSTRAINT ex_room_block_overlap
    EXCLUDE USING gist (room_id WITH =, during WITH &&);
```

## 8 SQL 任务示例（报告第 4 章 / 演示可直接执行）

以下 8 条与功能清单对应，全部为多表关联或统计查询（完整脚本见 `sql/04_queries.sql`，实测记录见 `docs/05`）：

1. **指定日期区间的可用房间**（F03）
   ```sql
   SELECT room_no, room_type_name, capacity, base_price, avg_price, total_price
   FROM fn_available_rooms(DATE '2026-12-20', DATE '2026-12-22', NULL);
   ```
   显式写法（与函数逐条等价：房型在售 + 房态不是维修/停用 + 无订单相交 + 无维修/停用区间相交）：
   ```sql
   SELECT r.room_no, rt.name AS room_type, rt.capacity, rt.base_price
   FROM room r
   JOIN room_type rt ON rt.id = r.room_type_id
   WHERE rt.is_active
     AND r.status NOT IN ('maintenance', 'disabled')
     AND NOT EXISTS (
       SELECT 1 FROM reservation v
       WHERE v.room_id = r.id
         AND v.status IN ('pending', 'confirmed', 'checked_in')
         AND v.during && daterange($1::date, $2::date, '[)')
     )
     AND NOT EXISTS (
       SELECT 1 FROM room_block b
       WHERE b.room_id = r.id
         AND b.during && daterange($1::date, $2::date, '[)')
     )
   ORDER BY r.floor, r.room_no;
   ```
2. **某客户的历史入住信息**（F09 明细，多表 JOIN：customer → reservation → room → check_in_record → payment）
3. **各房型月度入住率**（已售房夜 / 可售房夜，可售房夜扣除维修停用；`generate_series` + `date_trunc`）
4. **月度营业收入按支付方式拆分**（按 `check_in_record.actual_checkout_at` 归月，押金不计收入，退款冲减）
