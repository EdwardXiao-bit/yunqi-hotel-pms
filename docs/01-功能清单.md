## 2 项目描述

### 2.1 一句话描述（提交材料抬头用，≤ 100 字）

> 面向中小型酒店的客房管理系统：客户按日期区间查询可用房间并在线预订，前台办理入住、退房与费用结算并调度房态，管理员维护房型、房间与价格并查看入住率和营业收入统计；数据库层用日期区间排他约束保证同一房间在重叠日期内绝不会被重复预订。

### 2.2 完整项目描述

酒店客房业务的核心矛盾是“房间在时间维度上的独占性”：同一间房在同一晚只能卖给一位客户，而一位客户可能连续住多晚、也可能续住或提前退房。本系统把“预订”“入住”“结算”“房态”建成相互关联的数据对象，覆盖：

- **客户侧**：按入住/离店日期、房型、人数查询可用房间；提交预订、查看与取消自己的预订；查看历史入住与消费记录。
- **前台侧**：核验预订办理入住、办理退房并结算房费与增值服务、处理未到店与取消、调度房态（清洁中/维修中）。
- **管理员侧**：维护房型、房间、按日期区间定价、员工账号，查看入住率、营业收入、热门房型、长期空闲房间等统计。

系统不扩展为完整酒店信息系统（不含会员营销、渠道直连、实时房态硬件对接），聚焦预订—入住—退房—统计主链路。

## 5 业务规则（功能清单背后的约束，报告 3.2 会用）

1. 离店日期必须晚于入住日期。
2. 同一房间在 `[入住, 离店)` 半开区间内不得有两个有效预订（待确认 / 已确认 / 已入住）。
3. 房态为“维修中”“停用”的房间不可被预订或办理入住。
4. 已入住的预订不可取消；已退房的预订不可再次办理入住。
5. 房号在全部房间内唯一；同一房型在同一日期区间的价格方案不得重叠。
6. 结算金额 = 实际入住天数 × 适用房价 + 增值服务费用 − 已付押金，且不得为负。
7. 未到店（no-show）与取消必须释放房间占用，房态回到“可用”。

## 7 数据库表规划（供 02-数据库设计.md 展开）

| # | 表 | 说明 | 关键约束 |
| --- | --- | --- | --- |
| 1 | `app_user` | 账号与角色（客户/前台/管理员） | `username UNIQUE`、`role CHECK` |
| 2 | `customer` | 客户档案 | `phone UNIQUE`、`id_card UNIQUE` |
| 3 | `room_type` | 房型 | `name UNIQUE`、`CHECK (capacity > 0)`、`CHECK (base_price >= 0)` |
| 4 | `room` | 具体房间 | `room_no UNIQUE`、`status CHECK IN ('available','reserved','occupied','cleaning','maintenance','disabled')` |
| 5 | `rate_plan` | 按日期区间的价格方案 | `EXCLUDE (room_type_id =, daterange(valid_from, valid_to, '[]') &&)`、`CHECK (price >= 0)` |
| 6 | `reservation` | 预订主表 | **房间日期区间排他**（见下）、`CHECK (check_out_date > check_in_date)`、`status CHECK IN ('pending','confirmed','checked_in','checked_out','cancelled','no_show')` |
| 7 | `check_in_record` | 入住与结算记录 | `UNIQUE (reservation_id)`、`CHECK (actual_checkout_at IS NULL OR actual_checkout_at >= check_in_at)`、金额 `>= 0` |
| 8 | `payment` | 支付/押金流水 | `method CHECK`、`CHECK (amount >= 0)` |
| 9 | `room_status_log` | 房态变更日志（必选，用于状态可追溯） | FK 房号与操作人 |
| 10 | `service_item` / `service_order` | 增值服务（可选，若做则并入 F07） | `CHECK (quantity > 0)` |

核心约束（答辩主攻，报告 3.2.2 附代码）：

```sql
-- 同一房间在重叠日期内不得重复预订（半开区间，退房当天可再次入住）
ALTER TABLE reservation ADD CONSTRAINT ex_room_date_overlap
    EXCLUDE USING gist (
        room_id WITH =,
        daterange(check_in_date, check_out_date, '[)') WITH &&
    ) WHERE (status IN ('pending', 'confirmed', 'checked_in'));
```

## 8 SQL 任务示例（报告第 4 章 / 演示可直接执行）

以下 6 条与功能清单对应，全部为多表关联或统计查询：

1. **指定日期区间的可用房间**（F03）
   ```sql
   SELECT r.room_no, rt.name AS room_type, rt.capacity, rt.base_price
   FROM room r
   JOIN room_type rt ON rt.id = r.room_type_id
   WHERE r.status IN ('available', 'reserved')
     AND NOT EXISTS (
       SELECT 1 FROM reservation v
       WHERE v.room_id = r.id
         AND v.status IN ('pending', 'confirmed', 'checked_in')
         AND daterange(v.check_in_date, v.check_out_date, '[)')
             && daterange($1::date, $2::date, '[)')
     )
   ORDER BY rt.base_price;
   ```
2. **某客户的历史入住信息**（F09 明细，多表 JOIN：customer → reservation → room → check_in_record → payment）
3. **各房型月度入住率**（已售房夜 / 可售房夜，`generate_series` + `date_trunc`）
4. **月度营业收入按支付方式拆分**（`date_trunc('month', paid_at)` + `GROUP BY`）
5. **最受欢迎房型 Top 3**（订单数 + 房夜数，`RANK() OVER`）
6. **长期空闲房间与取消率**（近 90 天无预订；`FILTER (WHERE status='cancelled')` 占比）
