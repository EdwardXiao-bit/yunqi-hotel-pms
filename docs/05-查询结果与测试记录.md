## 0 执行方式与环境

```powershell
chcp 65001
$env:LC_ALL = 'C'
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d yunqi_hotel `
    -v ON_ERROR_STOP=1 -P pager=off -f "sql/04_queries.sql" -o "work/04_queries_out.txt"
```

- `-P pager=off`：否则终端停在 `-- More --`。
- `$env:LC_ALL='C'`：把 psql 自身的提示语（`(35 行记录)`）切成 `(35 rows)`，否则这行以 GBK 字节混入 UTF-8 输出文件。
- **已知 Windows 终端问题**：psql 会把查询**数据**按控制台码页转换输出，但服务端**消息**（`NOTICE`/`ERROR`）按客户端编码原样输出，中文在 cp936 终端必乱码；psql 自带的中文消息前缀（`注意:`）改环境变量无效。→ 脚本里的 `RAISE NOTICE` 一律写 ASCII；看中文结果用 `Get-Content work/04_queries_out.txt -Encoding UTF8` 或直接用编辑器打开。
- `NOTICE` 走 stderr，不进 `-o` 文件；Q8 的自检靠 `DO` 块「不通过就 `RAISE EXCEPTION`」来失败，落盘文件里只看得到 `DO`。

### 2.6 Q8 约束证据

- Q8 是一个 `DO` 块，两段断言：
  1. 取一条 `confirmed` 预订的房间与区间，换客户原样插入 → 必须被 `ex_reservation_room_overlap` 以 **`23P01`** 拒绝；
  2. 取该房间区间登记一段维修封禁 → 必须被 `fn_check_room_block_order` 以 **`23514`** 拒绝。
- 任一段未按预期拦截就 `RAISE EXCEPTION` 使脚本中止（`ON_ERROR_STOP=1`）；本次运行正常打印 `DO` 并继续到「04_queries.sql 执行完成」，说明两段断言均通过。
- `NOTICE` 文本（ASCII，走 stderr）形如：`NOTICE: Q8 OK: room <id> interval [<in>, <out>) rejected by ex_reservation_room_overlap, SQLSTATE=23P01`。
- 与 `sql/02_constraints.sql` 末尾 DO 块的自检结论一致；Django 侧按 `psycopg2.errors.ExclusionViolation` + `diag.constraint_name`（`23P01`）与 `psycopg2.errors.CheckViolation`（`23514`）分别映射中文提示（见 `docs/02` §11）。
