# 页面与表单约定（T4 契约，2026-10-30 先行落盘）

> 目的：9 个功能对应的页面 **URL、模板路径、表单字段、负责人** 先定死，两人并行写页面时不会互相覆盖模板文件，也不会到联调才发现接口对不上。
> 约定优先级：本文件 > 各自实现时的自由发挥；改了页面就同步改本文件（含负责人）。
> 技术基线：Django 模板 + 表单 POST（`{% csrf_token %}`）+ 服务端渲染；AdminLTE 3.2 / Bootstrap 4.6，资源在 `static/vendor/adminlte/`，**不用 CDN**。

## 2 URL 命名与分区

- 客户区：`/`、`/rooms/...`、`/reservations/...`、`/my/...` —— 前缀 `/my/` 表示“当前登录客户自己的数据”。
- 前台区：`/reception/...` —— 需 `role_required('receptionist', 'admin')`。
- 管理区：`/manage/...` —— 需 `role_required('admin')`；**不复用 Django Admin 做业务页面**（F01 可用 Admin 注册辅助，但页面仍在 P10）。
- 所有写操作只接受 POST（`@require_POST` 或表单视图内判断），成功后 `redirect()` + `messages.success()`，失败回显原页 + `messages.error()`。
- URL 统一 `app_name = 'core'`，模板里用 `{% url 'core:available_rooms' %}`，禁止硬编码路径。

## 3 表单字段契约

字段名与 `sql/01_schema.sql` 列名对齐（`snake_case`），Django Form 的 `label` 用中文，`help_text` 写清约束来源（便于答辩指认“这条是数据库 CHECK 挡的”）。

### F03 可用房查询（P02，GET）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `check_in_date` | date | 必填；`type=date`，默认明天 |
| `check_out_date` | date | 必填；默认后天；校验 `>` `check_in_date`（E01） |
| `room_type_id` | select | 可空＝全部房型；选项来自 `room_type WHERE is_active` |
| `capacity` | number | 可空＝不限；用于筛容纳人数 |

### F04 预订提交（P03，POST）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `room_id` | hidden | 由 P02 列表带入，只读展示房号/房型/首晚价 |
| `check_in_date` / `check_out_date` | date | 从 P02 带入，可改但重新校验 |
| `guest_count` | number | 1–8，超过房型 `capacity` 时提示 |
| `guest_name` / `guest_phone` | text | 联系人（可与账号资料不同） |
| `remark` | textarea | ≤200 字 |

提交后：成功 → `reservation` 生成 `reservation_no`，跳 P04 详情；冲突（23P01）→ 回显原页 + “该房间在所选日期已被预订，请换一间或调整日期”（E02）；同客户重复（23505 + `uq_reservation_active_customer`）→ “您已提交过相同区间、相同房间的预订”（E03）。

### F05 预订管理 / 取消（P04、P06；POST）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | select（筛选，GET） | pending / confirmed / checked_in / checked_out / cancelled / no_show |
| `date_from` / `date_to` | date（筛选，GET） | 按 `check_in_date` 过滤 |
| `keyword` | text（筛选，GET） | 预订号 / 客户姓名 / 手机号模糊匹配 |
| `action` | select（POST） | `confirm` / `cancel` —— 走同一个端点，服务端校验状态机（E05） |

破坏性操作（取消）用 SweetAlert2 二次确认；服务端仍必须再校验一次状态机，不靠前端按钮禁用。

### F06 入住办理（P07，POST）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `reservation_id` | select / hidden | 已有预订走 hidden；散客入住时为空 |
| `guest_name` / `guest_phone` / `guest_id_card` | text | 与预订客户一致时自动带出，可改（实际入住人可能不同） |
| `room_id` | select | 散客入住必填；仅列出 `status='available'` 且该区间无冲突的房间 |
| `deposit_amount` | number | 默认 200.00，`≥0` |
| `remark` | textarea | ≤200 字 |

提交成功：写 `check_in_record` + `reservation.status='checked_in'`（同事务）。**房态 4 态只表达物理可用性，不写「入住中」**——占用由订单一侧推导；若入住前房间是 `cleaning`，须先置回 `available` 再办理（`trg_room_status_log` 自动写变更日志，应用层不手写）。

### F07 退房结算（P08，POST）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `service_item_id` / `quantity` | select / number | 可多行（`formset` 或 JS 追加行）；单价取 `service_item.price` 快照进 `unit_price` |
| `extra_room_charge` | number | 超时/加收房费，默认 0 |
| `payments[]` | 多行 | `kind`（deposit/room_fee/service_fee/refund）+ `method`（cash/card/wechat/alipay）+ `amount` + `paid_at` |
| `actual_checkout_at` | datetime | 默认 `now()`；不得早于 `check_in_at` |

结算页必须显示：`v_check_in_detail` 的 `total_charge` / `settled_amount` / `balance`，押金不足时提示补收金额（E07）。

### F01 房型与价格维护（P10，POST）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `room_type`：`name` / `bed_type` / `area` / `capacity` / `base_price` / `description` / `is_active` | 混合 | `bed_type` 六个选项与 CHECK 一致；`capacity` 1–8 |
| `rate_plan`：`name` / `price` / `valid_from` / `valid_to` | 混合 | 区间重叠时数据库抛 23P01（`ex_rate_plan_no_overlap`）→ “该房型在此日期区间已有价格方案” |
| 删除房型 | POST | 有房间/预订引用时数据库 RESTRICT 报错（E08）→ 提示“改为停用” |

### F09 统计报表（P11，GET）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date_from` / `date_to` | date | 默认最近 30 天；落库查询直接用区间参数 |
| `room_type_id` | select | 可空＝全部 |

## 4 模板与样式约定

- 目录：`templates/base.html`、`templates/login.html`、`templates/partials/*.html`、`templates/customer/*`、`templates/reception/*`、`templates/manage/*`、`templates/errors/*`。
- 每个业务页只填 `{% block content %}`；页面标题用 `{% block page_title %}`，面包屑用 `{% block breadcrumb %}`。
- 表格统一 `.table.table-hover.table-sm`；筛选表单 `.form-inline`；操作按钮 `.btn-sm`；金额右对齐并保留 2 位小数。
- 提示：`messages` → `partials/messages.html`（Bootstrap alert，带 `alert-dismissible`）；表单字段错误 → `{{ field.errors }}` 配 `.invalid-feedback` + `.is-invalid`。
- 分页：服务端 `Paginator`，每页 20 条（预订/入住/支付列表），模板片段 `partials/pagination.html` 复用；**不用 DataTables 前端分页**。
- 日期控件：DateRangePicker（moment）只用于筛选区间；单字段用原生 `type=date`。
- 中文观感：`static/css/site.css` 补中文字体栈与表格/表单字号；不覆盖 AdminLTE 主色（答辩截图统一）。

## 5 权限与错误页

- 三端入口按角色：`customer` 只能进客户区；`receptionist` 进前台区（首页 `/reception/`）；`admin` 全通。
- 越权访问统一由 `role_required` 装饰器 → `PermissionDenied` → `templates/errors/403.html`（T13 定稿，配色与后台一致）。
- 数据库异常统一在视图层映射（见 `docs/02` §11）：23P01 / 23505 / 23514 / RESTRICT 删除 → 中文提示，页面顶部 alert，不暴露 SQLSTATE。

## 6 与 WBS 的对应

- 前端工作量**不单列人日**，随各功能任务一起交付；`docs/03` §4.4「前端实现节奏」按本文档的页面清单排时间窗。
- 页面契约变更流程：改本文件 → 通知对方 → 同步改 `docs/03` §4.4（时间窗不变则只改行内容）。
- 联调约定：页面先接真实视图（不做 mock 数据），后端 SQL 未就绪时用 `sql/03_seed.sql` 的数据直接查库，避免“假数据页面”。
